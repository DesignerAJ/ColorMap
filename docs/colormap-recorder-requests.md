# colormap-recorder 수정 요청서

**대상 파일:** `colormap-recorder.html` (Mapbox GL JS 기반 카메라 경로 녹화 도구)
**작성일:** 2026-08-24

## 작업 지침 (Claude Code용)

- 각 항목은 독립적으로 처리 가능. **P0 → P1 → P2 순서**로 진행.
- 항목마다 `현상 / 기대 동작 / 원인 추정 / 완료 조건`이 있음. **원인 추정은 가설이므로 실제 코드를 먼저 확인하고 검증할 것.**
- 하나의 항목을 끝낼 때마다 커밋을 분리할 것 (`fix: 알래스카 카메라 이동`, `fix: 국경선 레이어 순서` 등).
- 레이어 순서 / 스타일 관련 수정은 **6개 스타일 전부**에서 확인 필요: `단색지형`, `단색`, `위성사진`, `지형도`, `모노톤`, `일반지도`.

## P0 — 명백한 버그

### 1. 알래스카 선택 시 카메라가 엉뚱한 곳으로 이동

**현상**
행정구역에서 알래스카 선택 시 알래스카가 아닌 전혀 다른 위치로 카메라가 이동함.

**기대 동작**
선택한 행정구역의 실제 영역에 카메라가 맞춰짐.

**원인 추정 (검증 필요)**
알래스카는 **날짜변경선(경도 ±180°)을 넘어감** (서경 약 -172° ~ 동경 약 173°).
경도 최소/최대를 단순 비교해 bbox를 만들면 `[-172, 173]` 같은 값이 나오고, 그 중심은 알래스카가 아니라 **지구 반대편(대서양/아프리카 부근)**이 됨.

**같이 고쳐야 할 유사 케이스 — 반드시 함께 점검**

날짜변경선을 넘는 지역:

- 러시아 (추코트카 자치구)
- 피지, 키리바시, 뉴질랜드(채텀 제도)

본토와 멀리 떨어진 영토를 가져 bbox가 비정상적으로 커지는 지역:

- 미국 (본토 + 알래스카 + 하와이)
- 프랑스 (본토 + 프랑스령 기아나, 레위니옹, 뉴칼레도니아)
- 덴마크 (본토 + 그린란드)
- 네덜란드 (본토 + 카리브 자치령)
- 스페인 (본토 + 카나리아 제도), 포르투갈 (본토 + 아조레스, 마데이라)
- 노르웨이 (본토 + 스발바르), 에콰도르 (본토 + 갈라파고스), 칠레 (본토 + 이스터섬)

**작업 방향 제안**

1. bbox 계산 로직을 공통 유틸 함수로 분리 (현재 여러 곳에 흩어져 있다면 통합).
1. 날짜변경선 처리: 경도 폭이 180°를 넘으면 음수 경도에 +360을 더해 연속 좌표계로 변환 후 bbox 계산 → 결과를 다시 정규화.
1. 다중 폴리곤: 전체를 감싸는 bbox 대신 **면적이 가장 큰 폴리곤 기준**으로 카메라를 맞추는 옵션 고려 (미국 선택 시 태평양 한가운데가 잡히는 문제 방지).
1. `map.fitBounds()`에 `{ padding }`을 주고, 계산된 bbox가 비정상(경도 폭 > 180° 등)일 경우 경고 로그를 남길 것.

**완료 조건**

- 알래스카, 러시아, 미국, 프랑스, 덴마크 선택 시 각각 의도한 영역이 화면에 잡힘.
- 기존에 정상 동작하던 일반 국가(한국, 일본, 독일 등)에 회귀 없음.

### 2. 대한민국 국가 + 시·도 동시 색칠 시 레이어 순서가 반대

**현상**

- 해외: 국가 레이어 위에 행정구역 레이어 → 정상.
- 대한민국: 시·도 레이어가 국가 레이어 **아래**에 위치 → 시·도 색이 국가 색에 가려짐.

**기대 동작**
대한민국도 해외와 동일하게 **시·도 레이어가 국가 레이어보다 위**에 오도록.

**원인 추정**
한국 GeoJSON 레이어를 추가하는 시점이 국가 레이어보다 이른 경우, 또는 `map.addLayer(layer, beforeId)`의 `beforeId` 지정이 해외 경로와 다름.

**완료 조건**
대한민국을 국가 색칠한 상태에서 시·도를 색칠하면 시·도 색이 보임. 6개 스타일 전부 확인.

### 3. 조절 불가능한 흰색 국경선 레이어가 남아 있음

**현상**
지도 디자인에서 국경선 두께/투명도를 조절하면 조절 자체는 되지만, **투명도를 0으로 만들어도 흰색 국경선이 그대로 남음** (한국/북한 사이 국경선만 예외적으로 사라짐).

스타일별 관찰 결과:

|스타일   |흰색(조절 불가) 레이어 상태                         |
|------|-----------------------------------------|
|단색지형  |조절 가능 레이어보다 **아래**에 있음                   |
|단색    |조절 가능 레이어보다 **아래**에 있음                   |
|위성사진  |한국/북한 국경만 조절 가능 레이어가 보이고, 나머지는 흰색 레이어만 보임|
|지형도   |흰색 레이어가 조절 가능 레이어 **위**에 있음              |
|모노톤   |흰색 레이어 안 보임 — **정상**                     |
|일반지도|조절 가능 레이어가 아래에 있으나 문제 없어 보임              |

**원인 추정**
Mapbox 기본 스타일에 내장된 `admin-0-boundary` / `admin-0-boundary-bg` / `admin-1-boundary` 계열 레이어가 제거되지 않고 남아 있음. 커스텀 국경선 레이어는 따로 그려지고 있어서 두 겹이 됨. 한국/북한 국경선만 정상인 건 그 구간만 커스텀 GeoJSON으로 그리고 있기 때문으로 보임.

**작업 방향 제안**

- 스타일 로드(`style.load`) 직후 `map.getStyle().layers`를 순회해 `admin` 계열 레이어를 찾아 목록화 → 로그로 출력해 실제 ID 확인.
- 해당 레이어들을 `map.setLayoutProperty(id, 'visibility', 'none')` 처리하거나, 커스텀 국경선 컨트롤에 **함께 연동**시킬 것 (숨기는 쪽이 단순).
- **스타일 전환 때마다 다시 적용되어야 함** — 스타일을 바꾸면 레이어가 초기화되므로 `style.load` 이벤트에 훅을 걸 것.

**완료 조건**
6개 스타일 전부에서 국경선 투명도 0 → 국경선이 완전히 사라짐.

### 4. 한국·북한 행정구역선만 점선이 적용되지 않음

**현상**
행정구역선의 색상/투명도/두께는 전 국가 정상 동작. 그러나 점선으로 바꾸면 **한국과 북한만 점선으로 보이지 않음**. 전체 스타일 공통.

**원인 추정**
한국/북한 GeoJSON의 정점 밀도가 매우 높아, `line-dasharray` 패턴 간격보다 선분 길이가 짧아 점선이 시각적으로 뭉개짐.

**작업 방향 제안**

- `line-dasharray` 값을 선 두께에 비례해 스케일링 (예: `[2, 2]` 고정이 아니라 두께 대비 비율로).
- 또는 한국/북한 GeoJSON에 단순화(simplify) 적용 — turf.js `simplify` 또는 사전 처리로 정점 수를 줄인 별도 데이터 준비.
- 두 방법 중 렌더링 품질 손실이 적은 쪽 선택. 단순화 시 2025년 경계(대구의 군위군 편입) 유지 확인 필수.

**완료 조건**
한국/북한을 포함한 모든 지역에서 점선이 점선으로 보임.

-----

### 5. 녹화 설정 ‘이동 중 줌아웃’이 ‘많이’에서도 반응 없음

**현상**
녹화 설정의 ‘이동 중 줌아웃’ 값을 ‘많이’로 설정해도 카메라 줌아웃 변화가 없음.

**기대 동작**
설정값에 따라 이동 중 줌아웃 폭이 눈에 띄게 달라짐.

**원인 추정**
설정값이 UI에서만 바뀌고 실제 카메라 애니메이션 함수(`flyTo`의 `curve` / `speed`, 또는 중간 줌 레벨 계산)에 전달되지 않음. 값이 전달되더라도 상수로 덮어써지고 있을 가능성.

**작업 방향 제안**
설정값 → 애니메이션 파라미터 경로를 따라가며 콘솔 로그로 실제 반영 여부 확인. 단계별 수치를 명시적으로 정의할 것 (예: 없음 / 조금 / 보통 / 많이 → 줌 감소량 0 / 1 / 2 / 3.5 단계).

**완료 조건**
‘없음’과 ‘많이’의 녹화 결과가 육안으로 명확히 구분됨.

## P1 — 개선

### 6. 주요국 외 행정구역 형태가 각진 다각형으로 표시됨

**현상**
임의 지정된 주요 국가가 아닌 경우, 행정구역 색칠 영역이 매우 거칠고 각진 다각형으로 나옴. 같은 지역의 행정구역 **선**은 정상적으로 세밀함.

**기대 동작**
색칠 영역이 행정구역 선과 동일한 형태/해상도로 표시됨.

**사용자 제안**
용량 문제라면 **필요할 때만 해당 국가의 행정구역 데이터를 가져와 쓰고, 일정 시간 후 해제**하는 온디맨드 방식은 어떤지.

**작업 방향 제안**

1. 먼저 현황 파악: 색칠용 데이터와 선 표시용 데이터의 출처가 다른지 확인. 다르다면 **선 데이터를 색칠에도 재사용**하는 것이 가장 간단한 해결일 수 있음.
1. 온디맨드가 필요하다면:
- 국가 선택 시 해당 국가 행정구역 GeoJSON만 fetch → `map.addSource`
- `Map` 기반 캐시에 보관, LRU로 최대 3~5개국 유지, 초과 시 오래된 소스 `removeSource`
- 로딩 중 표시 필요 (녹화 중 로딩이 걸리면 안 되므로, **녹화 시작 전 필요한 데이터가 모두 로드되었는지 확인하는 가드** 추가)
1. 데이터 소스 후보 조사 필요 (Natural Earth admin-1 고해상도, geoBoundaries 등).

**완료 조건**
임의의 비주요국을 선택해도 색칠 영역과 행정구역 선이 어긋나지 않음.

### 7. 먼 거리 이동 시 카메라가 경로선을 따라가지 않음 + 경로선 관련 개선

**7-1. 아크 경로 이동 (핵심)**

현상: 서울 → 런던 아크 경로를 그린 뒤 이동하면 카메라는 **최단거리(직선)**로 움직여, 화면에 그려진 아크 화살표가 화면 밖으로 벗어남.

기대 동작: 아크 경로를 선택한 경우 **카메라도 아크 경로를 따라** 이동해 화살표가 계속 화면 안에 유지됨.

작업 방향: 아크 경로를 생성하는 좌표 배열을 그대로 카메라 경로로 사용. `flyTo` 대신 프레임 단위로 `easeTo`/`jumpTo` 하며 경로 좌표를 보간. 진행률에 따라 줌도 조절(중간에 줌아웃 → 도착 시 줌인)해 전체 경로가 화면에 담기도록.

**7-2. 도로 경로는 예외**

도로 경로 선택 시에는 경로를 따라가면 카메라가 심하게 흔들리므로, **최단 경로로 이동**하는 현재 방식 유지.

**7-3. 경로선 타입에 ‘직선’ 추가**

포인트 간 단순 직선 타입을 옵션으로 추가.

**7-4. 경로선 기본값 변경 (의견)**

현재 기본값인 도로 경로 대신 **아크 또는 직선을 기본값**으로. 뉴스 그래픽 특성상 도로 경로보다 아크/직선 사용 빈도가 높을 것으로 보임 — 최종 결정은 사용자 확인 후 반영.

**완료 조건**
서울 → 런던 아크 경로 녹화 시 화살표가 전 구간 화면 안에 유지됨. 도로 경로는 기존 동작 유지.

### 8. 시·도 검색 목록에 풀네임/약칭 중복 표시

**현상**
‘시도 검색’ 칸을 누르면 선택지가 전부 뜨는데, `충북`과 `충청북도`가 **둘 다 항목으로 표시**되어 중복이 많음.

**기대 동작**

- **표시되는 선택지는 약칭만** (충북, 전남, 경기 등)
- **검색 매칭은 풀네임·약칭 둘 다 유지** (`충청북도` 입력해도 `충북` 항목이 검색됨)

**작업 방향**
데이터 구조를 `{ label: '충북', aliases: ['충청북도', '충북'] }` 형태로 변경. 렌더링은 `label`만, 필터링은 `aliases` 전체 대상.

**완료 조건**
목록에 17개 광역시·도가 중복 없이 약칭으로만 표시되고, 풀네임 검색도 정상 동작.

-----

### 9. 한국어로 해외 도시 검색 시 국내 상호명이 검색됨

**현상**
좌상단 검색창에 `파리` 입력 → 프랑스 파리가 아니라 **국내의 ‘파리’가 들어간 상호명 건물들**이 나옴.

**사용자 의견**
Vworld 결과에서 가게 이름 같은 POI(상호)를 제외할 수 있는지.

**작업 방향 제안**

1. Vworld API에 검색 카테고리 파라미터가 있는지 확인 (지명/도로명주소/지번 vs POI 분리 가능 여부). 가능하면 **POI 타입 제외**.
1. 제외가 불가능하다면 결과 병합 전략 변경:
- 국내 검색(Vworld)과 해외 검색(Mapbox Geocoding 등)을 **동시에 호출**
- 정렬 우선순위: 행정지명 > 도로명주소 > POI
- 결과 항목에 출처/종류 배지 표시 (예: `파리 · 프랑스 일드프랑스` / `파리바게트 ○○점 · 상호`)
1. 최소 목표: `파리`, `런던`, `도쿄`, `베를린` 검색 시 해당 해외 도시가 **첫 번째 결과**로 나올 것.

**완료 조건**
위 4개 도시 한국어 검색이 모두 해외 도시를 최상단에 반환. 국내 지명 검색 회귀 없음.

## P2 — 기능 제안

### 10. 핀 저장 / 다중 핀 지정

**요청**
구글맵처럼 여러 지점에 핀을 찍어 저장해두고, 여러 군데를 동시에 표시한 상태로 캡처.
국가 단위뿐 아니라 검색으로 나온 지역들도 핀으로 지정 가능하게.

**선행 확인 필요**

> 사용자 메모: “근데 이거는 지금 있지 않나…?”

**→ 먼저 현재 코드에 다중 핀 기능이 이미 있는지 확인할 것.** 있다면 UI 접근성 문제(기능이 숨어 있음)일 가능성이 높으므로, 새로 만들지 말고 **발견 가능성 개선**으로 방향을 잡을 것. 없다면 아래대로 구현.

**구현 시 범위**

- 검색 결과에서 ‘핀 추가’ → 핀 목록에 누적
- 핀 목록 UI: 이름 표시, 개별 삭제, 전체 삭제
- 핀 여러 개가 모두 보이도록 화면 맞추기 버튼
- 핀 세트를 로컬에 저장/불러오기 (localStorage)
